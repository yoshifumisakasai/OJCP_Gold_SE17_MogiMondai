#Console クラスのメソッド仕様  

*Console は「端末専用の入出力」を扱う特殊クラス*
*標準出力のような println を持たず、フォーマット出力（printf）と write 系のみを提供している。*  


□クラスConsole  
java.lang.Object  
java.io.Console  
`すべての実装されたインタフェース:Flushable`  

`public final class Console extends Object implements Flushable`  
現在のJava仮想マシンに関連付けられている文字ベースのコンソール・デバイスがある場合に、そのコンソール・デバイスにアクセスするためのメソッドです。  





#print, println, printfの違いについて
 **print / println / printf の違いは「改行の有無」と「フォーマット指定の可否」 **

〇結論（まずここだけ理解すればOK）  
`print`    
→ 改行しない。文字列をそのまま出力するだけ。  
*☆内部的には write() を呼んでいるだけで、出力後にカーソルは同じ行に残る*  

`println`  
→ 出力して 最後に改行する。  
*☆print() の後に 改行コードを追加している*  

`printf`  
→ フォーマット（書式）を指定して出力できる。  
改行は自動では入らないので自分で \n を書く  



#フォーマット指定子  
□ポイント  
`printf は内部で Formatter を使っていて、フォーマット文字列を解析し、% から始まる部分を「変換指定子」として扱う。`  


`%s`   
「%s」は文字列を埋め込むためのフォーマット指定子    
→ String（文字列）を埋め込む  
→ toString() が呼ばれるので、オブジェクトでも使える

`%d`    
「%d」は整数を埋め込むためのフォーマット指定子。     
→ decimal（10進数の整数）を埋め込む  
→ int, long, short, byte など整数型に使う  


・コード  
`System.out.printf("名前: %s, 年齢: %d%n", "コマツ", 30);`  

・出力  
`名前: コマツ, 年齢: 30`  

■🔍 カンマとフォーマット指定子の関係性（内部動作の視点）  

*printf は最初の引数（フォーマット文字列）を解析し、% を見つけるたびに「変換指定子」として登録する*  
*後ろの引数を “左から順番に” 変換指定子へ割り当てる*  
*カンマはその「複数引数の区切り」*  

`printf(format, arg1, arg2, arg3...)`  
という構造
**format の中の % の数と、後ろの引数の数が一致している必要がある**
