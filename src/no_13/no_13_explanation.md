#概要説明  

Sample インタフェースは 抽象メソッドが1つだけなので、関数型インタフェースとしてラムダ式で実装できる。  


□int test(int a, int b) に対応するラムダ式:  

`(a, b) -> a + b`  


〇型を明示する場合：  
`(int a, int b) -> a + b`  




#選択肢別

誤り  
A. Sample s = a + b;  
ラムダ式ではない  

*ラムダ式の構文になっておらず、ただの式であり、Sample 型に代入できない*  
→ 誤り  




誤り  
B. Sample s = (int a, b) -> { return a + b };
*パラメータの型指定は 両方書くか、両方書かないか のどちらか*  

*(int a, b) のように 片方だけ型を書くのは文法エラー*  
*ラムダ式の定義では、すべての引数に型を付けるか、すべて省略するかのどちらか*  
→ 誤り  




C. Sample s = (int a, int b) -> a + b;  
型を両方書いているので文法的に正しい  

戻り値が int で test(int,int) に合致  
→ 正しい  



誤り  
D. var s = (a, b) -> a + b;
**var は ローカル変数の型推論**  

`ラムダ式の型推論は ターゲット型（左辺の型）が必要*`  

`左辺が var だとターゲット型が決まらずコンパイルエラー` 
`varを使っただけでは、型情報が不足しているため、この式がどの関数型インタフェースを実装しているか分からず、コンパイルエラーが発生`   
→ 誤り



誤り  
E. Sample s = (a, b) -> { a + b };
`ブロック { ... } を使う場合は return が必須`  

**{ a + b } は式を評価しているだけで戻り値を返していない**  
→ 誤り






#ポイント整理まとめ(選択肢の正誤判断材料)  


・ブロック { ... } を使う場合は return が必須  


・var は ローカル変数の型推論では、ターゲット型（左辺の型）が必要  


・パラメータの型指定は 両方書くか、両方書かないか のどちらか  




#まず「ターゲット型」とは何か  

**Java のラムダ式は 「どの関数型インタフェースを実装するのか」 を左辺の型から判断する。**  

例：  
`Sample s = (a, b) -> a + b;`
このとき Java はこう判断する：  

左辺の型は Sample  
Sample の抽象メソッドは int test(int a, int b)  
ラムダ式 (a, b) -> a + b は test(int,int) の実装  

`左辺の型がラムダ式の型推論の起点になる、これが ターゲット型。`  



#var が使えない理由（本質）  

`var s = (a, b) -> a + b;`  
Java の判定：  

左辺の型が var → 具体的な型が書かれていない  
ラムダ式は「型がない匿名メソッド」なので、右辺だけでは型が決まらない  
どの関数型インタフェースを実装するのか判断できない  

つまり：
`ラムダ式は右辺だけでは型が決まらない。左辺の型が必要なのに、var は型を提供しない。`
