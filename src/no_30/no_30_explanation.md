#なぜ 0〜9 なのか（nextInt の仕様）
Random#nextInt(int bound) の仕様：

返す値の範囲：
`0　≤　値　< bound`  

今回の bound は 10  
※よって 0〜9 のどれかが返る




#1. ラムダ式の観点

`Supplier の抽象メソッド get() を ラムダ式で実装している`  

**() は引数なし、-> の右側が処理内容**  




#2. メソッド参照の観点  

`メソッド参照は 既存メソッドをそのまま使うだけ のときに使える`  

しかし今回の処理は：

new Random() でインスタンス生成  
nextInt(10) で乱数生成  

*この 2 ステップをまとめて行う既存メソッドは存在しない*  

**❌ よってメソッド参照にはできない**  



#3. 匿名クラスの観点  

※ラムダ式は 匿名クラスの省略記法  

匿名クラス：  
**Supplier の抽象メソッド get() をオーバーライドしている**

```
Supplier<Integer> s = new Supplier<Integer>() {
    @Override
    public Integer get() {
        return new Random().nextInt(10);
    }
};

```


□オーバーライド  
`オーバーライド（override）とは「親クラス（またはインタフェース）のメソッドを、子クラスが“同じシグネチャで”書き換えること」`  
`実行時には“子クラス側のメソッドが優先される”という仕組み`  



〇オーバーライドの成立条件（試験でも超重要）  
✔ メソッド名が同じ  
✔ 引数（型・数・順序）が完全一致  
✔ 戻り値の型が同じ（または共変戻り値 OK）  
✔ アクセス修飾子は親より“狭くできない”  
✔ 例外は親より“広くできない”  
✔ @Override を付けるとコンパイル時にチェックされる（推奨）
