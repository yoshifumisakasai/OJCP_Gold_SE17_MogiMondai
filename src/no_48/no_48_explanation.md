```
class B{
    void say() {
        System.out.println(this.msg); // C
    }
}

```


■選択肢：A  
〇正解は A（System.out.println(A.this.msg); に修正する）  
this.msg は B の msg を探すが、B には フィールド「msg」がない  

**this → B のインスタンス**   

B に msg がない → コンパイルエラー  

A の msg を参照したい場合、「A.this.msg」と書く必要がある  




■選択肢：D
 A を new A.B().say(); に修正すると、文法的に不可能  

なぜか？  
`B は 非 static の内部クラスなので、外側の A のインスタンスがないと生成できない`


`「非 static の内部クラス B は、外側クラス A のインスタンスに“ひも付いて”存在するため、A のインスタンスなしでは B を new できない」  `
**非 static 内部クラスは、外側クラスのインスタンスに寄生して存在するので、 newするには外側のインスタンスが必須**  




#Javaの内部クラス(2種類)：  

**①非 static 内部クラス（Inner class）**  



`非 static 内部クラスは、外側クラスのインスタンスに属するオブジェクトとして扱われる。`

```
A のインスタンス
 └── その中に B のインスタンスが存在する
```
という構造

コード例：
非 static 内部クラス（今回の B）

```
class A {
    class B {}
}

new A().new B();   // 必須
new A.B();         // コンパイルエラー
```


**②static 内部クラス（Nested class）**  

理由：B は A のインスタンスに依存しないから。

〇コード例：
static 内部クラス  

```
class A {
    static class B {}
}

new A.B();         // OK
new A().new B();   // コンパイルエラー
```



■static 内部クラスの本質  
static を付けると、内部クラスはこう扱われる：

```
A の中にあるだけの別クラス
（A のインスタンスとは無関係）
```


外側 A のフィールドにアクセスできない（static でない限り）

  *（外側の非 static フィールドにアクセス不可）*   

  *（外側の static フィールドにはアクセス可能）*    



**外側 A のインスタンスを保持しない**  

**外側 A のインスタンスがなくても new できる**  



□整理まとめ（Javaの内部クラスの仕組み）  
`static 内部クラスが「外側の非 static フィールドにアクセスできず、外側の static フィールドにはアクセスできる」のは、“static が外側インスタンスと無関係になる” という Java の言語仕様が理由。`  


`static を付けた瞬間に「外側のインスタンス」という概念が消える。`  
そのため、**非 static フィールド（インスタンスフィールド）には触れられない**  
しかし、 **static フィールド（クラスフィールド）には触れられる**  



`static 内部クラスは外側クラスのインスタンスを持たないため、外側のインスタンスフィールド（非 static）にアクセスできない。しかし、外側のクラスフィールド（static）にはアクセスできる`
